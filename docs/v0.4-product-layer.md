# v0.4.0 产品层说明

本文说明 0.4.0 在官方 DeepSeek Harness Web profile 外增加的桌面能力。项目不是
DeepSeek 官方 Desktop，而是一个 Electron 社区封装；官方 Agent、工具、Workspace
和会话协议仍是运行时事实来源。

## Agent Level

`src/agent-levels.cjs` 是可审计的策略表。每个档位都会同时改变并行工具上限、
最大 Agent steps，以及是否要求验证/失败修复：

| 档位 | Provider effort | 并行工具 | 基础 steps | 验证 | 修复 |
| --- | --- | ---: | ---: | --- | --- |
| Low | high（官方兼容边界） | 2 | 8 | 否 | 否 |
| Medium | high | 4 | 16 | 是 | 否 |
| High | high | 6 | 28 | 是 | 是 |
| Extra High | max | 8 | 48 | 是 | 是 |
| Max | max | 10 | 80 | 是 | 是 |

DeepSeek API 当前原生 effort 以 `high`/`max` 为准；Low/Medium 不是虚构的模型
枚举，而是 Desktop 层预算和验证策略。用户可以增加有限的 budget override，
最终值会在工作台状态中显示。

## Usage 与费用

桌面数据层位于 Electron `userData/data/app-state.json`，具有 schema version、
迁移、损坏回退、原子写入、上一版本备份和记录上限。只保存结构化 Token/模型/会话
元数据，不保存提示词、回复正文、图片或 API Key。来源包括：

1. 官方会话历史中的 `assistant/message.usage`；
2. DeepSeek Test Connection 的真实响应；
3. Vision Bridge 的真实响应 usage（如果 provider 返回）。

`src/pricing-metadata.json` 是版本化、带来源和生效日期的 USD/1M tokens 表；页面
始终称 `Estimated Cost`，不是服务商账单。余额栏不会用 Token 反推余额。由于当前
DeepSeek 公开 API 没有可靠、稳定的余额查询契约，状态为 `official-unavailable`，
页面提供 Billing 链接而不显示伪造金额。

## Browser 与 Computer Control

Browser 是可选的 `browser-plugin`，采用 Playwright Core 和系统 Edge/Chrome，使用
应用专用隔离 Profile，不复用个人浏览器 cookies。它支持打开/切换标签、导航、点击、
输入、读取、截图、等待和受边界约束的上传/下载。默认关闭，必须同时满足 Browser
开关和 Browser 权限；上传/下载默认需要确认，并限制在允许的工作区路径。

Web Search 仍是官方 Harness 的搜索工具，两者不会混用。Computer Control 不在此
版本启用：没有安全、可审计的跨窗口 STOP/审批闭环前保持 OFF/Deferred，UI 和报告
均不会声称已实现桌面鼠标键盘控制。

## 权限

权限 preset 为 Read Only、Safe Coding、Full Workspace、Browser Agent、Full Agent。
每次保存都会将 preset 作为规范来源，Computer 永远被强制为 false。Workbench 的
Terminal IPC 在权限关闭时拒绝请求；Browser 还需 Browser 设置开启。Workspace、
Harness sandbox 和项目规则（包括 `AGENTS.md`）仍优先于个人偏好。

## Profile 与隐私

Profile 只导出可移植偏好：语言、外观、Agent Level、预算、个性化、权限、Browser
策略和 Workspace 偏好。导出前会清空工作区、下载、临时目录和浏览器可执行路径。
校验器按字段名拒绝 API key、token、cookie、DPAPI、credential、password 等秘密字段。
真正的 DeepSeek/Vision Key 只在 Electron safeStorage（Windows DPAPI）中读写，渲染器
只能看到“已配置”和固定掩码。

Data & Privacy 页面只清理应用自己的日志、Usage、会话索引、handoff 历史、缓存和
临时数据；不会删除 Workspace 源码或 Git 历史。诊断与导出都做 Secret Redaction。

## Skills、插件和 Codex

Skills 读取项目 `.agents/skills` 和允许读取的用户 `.agents/skills`，不复制或修改
Codex 私有 `.codex/skills`。插件市场搜索的是公开 GitHub 元数据；未知仓库只能查看。
安装要求本地 pinned ref、allowlist、宽松许可证、合法 dsh manifest、归档路径和
符号链接边界检查，插件只能落在当前 profile 的 plugins 目录。

Codex 协作继续使用同一个真实项目目录、`.git`、`AGENTS.md`、`.agents/TASKS.md`、
`HANDOFF.md`、`MEMORY.md` 和锁文件。Codex 的 SQLite/JSONL/浏览器状态不是公开契约，
不会被修改；可选的官方 app-server adapter 只读列出精确 cwd 的 thread，并由用户
触发摘要。聊天因此是结构化 handoff，不是假装完整实时聊天同步。

## 版本化应用数据

应用数据和项目共享数据分开：应用全局数据在 Electron userData，项目交接状态在
真实 Workspace 的 `.agents/`。新字段必须走 schema migration；不要把个人路径、
密钥、cookies、日志和私人会话加入仓库。未来公开发布前应重新运行 license、audit、
secret scan，并人工复核外部 API 的条款和商标使用。
